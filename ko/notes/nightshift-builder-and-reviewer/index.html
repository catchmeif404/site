nightshift: 한 모델이 만들고 다른 모델이 검토해요

작성 2026-11-24 · catchmeif404

코딩 에이전트에게 아무도 보지 않는 동안 일을 맡기면 시시한 방식으로 문제가 생겨요. 내 체크아웃을 건드리거나, 결과를 어디에도 적지 않고 성공했다고 말하거나, 노트북이 잠들면 멈추거나, 돈이 걸린 변경을 그냥 머지해 버려요. nightshift는 에이전트 주변에서 이런 경우를 맡는 작은 도구예요. MIT 라이선스의 오픈소스이고 npm에는 @catchmeif404/nightshift로 올라가 있어요. 소스는 github.com/catchmeif404/nightshift에 있고, README는 현재 상태를 초기 단계(0.1)라고 적고 있어요.

무엇이고, 무엇이 아닌가요

nightshift는 내 컴퓨터에서 도는 무인 개발 큐예요. 보드에 티켓을 올리면 티켓마다 코딩 에이전트의 개발자 실행을 시작해요. 기본은 Claude Code sonnet이고 Codex도 쓸 수 있어요. 개발자는 자기 브랜치에서 변경을 만들어요. 그다음 별도의 검토자 실행이 시작되는데, 기본은 opus예요. 검토자는 작은 문제는 직접 고치고, 큰 문제는 한 번 더 돌려보내고, 사람이 정해야 하는 것은 멈춰 세워요.

nightshift는 코드를 직접 쓰지 않아요. 구현과 검토는 에이전트가 하고, nightshift는 다음 티켓을 고르고, 티켓마다 git worktree를 따로 주고, 에이전트 실행을 시작하고 이어 가고, 실행이 꼭 써야 하는 파일에서만 결과를 받아들이고, 재작업을 돌려보내고, 허용하면 통과한 것을 머지하고, 티켓을 최신 상태로 유지해요. 코드를 쓴 모델이 그 코드를 승인하는 모델이 되지는 않아요.

보드

보드는 티켓이 있는 곳이에요. README가 적은 종류는 이래요.

  • local-md(기본): .tickets/ 폴더의 마크다운 파일이에요.
  • github: GitHub Issues예요. nightshift:ready 같은 nightshift:* 라벨을 써요. 이슈는 곧 프롬프트이기 때문에 trustedAuthors가 연 이슈만 가져가요.
  • notion: Notion 데이터베이스예요. 속성과 상태 이름을 설정할 수 있어요.
  • command: 어떤 트래커든 쓸 수 있어요. list, set-status, note를 구현한 작은 실행 파일만 있으면 Linear, Jira, 스프레드시트도 보드가 돼요.

티켓에서 머지된 풀 리퀘스트까지

빠른 시작은 명령 네 줄이에요.

npm install -g @catchmeif404/nightshift
nightshift init --repo-path ~/code/my-app
nightshift add "Add a slugify helper" --project my-app
nightshift run

티켓은 이렇게 움직여요. 워커가 프로젝트의 ready 티켓을 가져가요. 프로젝트마다 워커는 하나이고 여러 프로젝트가 동시에 돌 수 있어요. 구현 단계는 새 worktree에서 돌고, 끝날 때 결과 파일에 PR <url>, BRANCH <name>, BLOCKED <why> 중 한 줄을 써야 해요. 검토 단계는 테스트를 돌리고 PASS, REWORK, NEEDS_HUMAN, BLOCKED 중 하나를 써요. REWORK이면 검토 메모를 들고 구현이 다시 돌고 검토자가 한 번 더 봐요. maxRework 기본값은 1이에요.

PASS면 티켓은 review로 가서 내가 머지하기를 기다려요. autoMerge를 켜면 nightshift가 직접 풀 리퀘스트를 머지하고 티켓은 done이 돼요. autoMerge는 기본이 꺼짐이에요. publish: "pr"이면 브랜치를 푸시하고 풀 리퀘스트를 열어요. "branch"이면 nightshift/t-1 같은 로컬 브랜치에서 기다려요.

사람이 정하는 관문

모델이 머지하면 안 되는 변경이 있어요. humanGates 기본값은 다섯 가지 전부예요. money, legal, destructive-data, outward-facing, product-direction이에요. 변경이 이 중 하나에 걸리면 검토자는 NEEDS_HUMAN으로 답하고 사람이 정해야 할 내용을 적어요. 티켓은 blocked가 돼요. 시작 가이드는 가격을 바꾸는 티켓을 예로 들어요. 별도로 gatePaths에 db/migration/** 같은 glob을 넣으면, 변경이 일치하는 파일을 건드릴 때 검토를 통과해도 autoMerge가 켜져 있어도 NEEDS_HUMAN이 돼요.

힘든 밤을 견디는 이유

  • 말이 아니라 파일이에요. 단계는 결과 파일을 정해진 형식으로 썼을 때만 끝난 것으로 쳐요. 읽을 수 없는 결과는 따로 치워 두고 그 단계를 다시 돌려요.
  • 끊긴 실행은 이어져요. 단계마다 세션 id가 고정되어 있어서 재부팅 뒤에도 다음 실행이 같은 세션을 이어 가요. 3번 끊기면(maxStageTries) 마지막 로그 줄을 이유로 달아 티켓을 막아요.
  • 사용량 한도는 기다려요. 에이전트가 초기화 시각이 있는 한도 메시지를 내면 시도로 세지 않고 초기화 뒤에 이어 가요.
  • 내 체크아웃은 그대로예요. 티켓마다 자기 worktree와 브랜치에서 일해요.

README에는 우리가 직접 쓰며 잰 수치가 하나 있어요. 앞선 bash 러너가 처음 12일 동안 티켓 225개를 구현과 검토에 통과시켰고, 그중 84%가 첫 검토에서 통과했다고 해요. 이 통과는 사람이 아니라 AI 검토자의 판정이고, README도 그렇게 밝히고 있어요.

Node 20 이상, git, 로그인된 Claude Code CLI가 필요해요. 파일을 고치고 명령을 실행할 수 있는 에이전트를 돌리는 도구라서, README는 그래도 괜찮은 컴퓨터와 저장소에서 쓰고, 믿을 수 있을 때까지 autoMerge를 끄고, trustedAuthors를 짧게 유지하라고 권해요.
