아무도 추적하지 않고 브라우저 게임 플레이 수 세기

작성 2026-11-24 · catchmeif404

마스크맨을 누가 하는지, 어떤 모드를 쓰는지, 로그라이크에서 어디까지 가는지는 알고 싶었어요. 그렇다고 플레이어 개인의 기록을 쌓고 싶지는 않았어요. 그래서 하루 단위로 이벤트 횟수만 세고, 누가 일으켰는지는 아무것도 저장하지 않는 방식으로 정했어요.

이벤트는 enum이고, 서버도 enum만 알아요

게임과 Worker는 src/net/stats.ts 파일 하나를 같이 써요. 여기에 모든 이벤트가 StatKey의 멤버로 정의돼 있어요.

export enum StatKey {
  VisitNew = 'visit.new',
  VisitSameDay = 'visit.sameday',
  MatchOnline = 'match.online',
  MatchRogue = 'match.rogue',
  RogueStart = 'rogue.start',
  RogueWon = 'rogue.won',
  // ...
}

Worker는 멤버가 아닌 값을 받지 않아요. 지어낸 키, 자유 입력 칸, 아이디를 실어 보내도 아무것도 더해지지 않아요. 키가 다루는 건 방문(이 기기의 첫 방문, 같은 날 또 방문, 다음 날, 일주일 안, 그 뒤), 언어, 터치와 PC, 모드별 대전 시작 수, 로그라이크 시작과 끝난 막, 머문 시간 구간, 첫 화면에서 누른 버튼, 버그 신고 버튼 클릭이에요. 새 이벤트는 enum 맨 뒤에 추가하는 것으로만 늘려요.

무엇을 저장하나요

Stats라는 Durable Object 하나가 SQLite 표 하나를 들고 있어요.

CREATE TABLE IF NOT EXISTS counts (
  day TEXT NOT NULL, key TEXT NOT NULL, n INTEGER NOT NULL,
  PRIMARY KEY (day, key))

이벤트가 오면 INSERT ... ON CONFLICT(day, key) DO UPDATE SET n = n + excluded.n으로 한 행에 더해요. 날짜는 한국 시간 기준이에요. 우리가 숫자를 한국 시간으로 읽기 때문이에요. 공개 엔드포인트 /api/stats?days=N은 하루별 합계를 돌려주고, 최대 90일까지예요.

이 표에 없는 것도 분명해요. 플레이어 아이디, IP 주소, 쿠키, 하루보다 잘게 쪼갠 시각이 없어요. 요청에서 적어 두는 건 키 이름과 횟수뿐이에요. 그래서 "어떤 방문자가 다시 왔나" 같은 질문에는 이 표로 답할 수 없어요.

아이디 없이 재방문 알기

사람들이 다시 오는지는 알고 싶었어요. 이건 브라우저가 기기 안에서 계산해요. 첫 방문 때 오늘 날짜를 localStorage에 저장해 두고, 다음에 열 때 그 날짜와 오늘을 비교해서 visit.d1, visit.d2_7 같은 구간 이름만 보내요. 서버는 그 날짜를 모르고, 두 방문을 이어 줄 값도 받지 않아요. 저장소가 막혀 있으면 새 방문으로 세요.

무료 요청 한도를 위해 묶어 보내기

처음에는 이벤트 하나마다 요청 하나를 보냈어요. 한 번 방문해서 열 판을 하면 요청이 열 번이 넘었어요. Cloudflare Workers 무료 플랜에는 하루 요청 한도가 있고, 같은 Worker가 게임 파일과 대전 방도 같이 맡고 있어서 집계가 그 한도를 갉아먹는 건 피하고 싶었어요.

v1.32부터는 페이지가 이벤트를 메모리에서 세어 두었다가 한꺼번에 보내요.

export function track(key: StatKey): void {
  pending.set(key, Math.min(MAX_STAT_COUNT, (pending.get(key) ?? 0) + 1));
  held += 1;
  if (held >= FLUSH_AT) flush();
}

방문 정보(종류, 언어, 기기)는 로드할 때 한 번 보내요. 나머지는 페이지가 숨겨지거나 닫힐 때까지 기다렸다가 {"c": {"match.cpu": 3, "rogue.start": 1}} 같은 본문 하나로 나가요. 그래서 판 수와 상관없이 방문 한 번에 요청이 약 두 번이에요. 한 세션이 아주 오래 열려 있으면 쌓인 이벤트가 60개가 될 때 보내고, 요청 하나가 키 하나에 더할 수 있는 값은 최대 500이에요.

전송은 가능하면 navigator.sendBeacon을 써서 탭을 닫아도 취소되지 않게 하고, 안 되면 keepalive를 준 fetch를 써요. 실패는 일부러 무시해요. 집계가 게임을 방해하면 안 되기 때문이에요. 업데이트 전에 열어 둔 페이지는 키당 한 번씩 보내는 예전 형식을 계속 보내서, Worker는 그 형식도 아직 받아요.

이 방식의 한계

합계만 세기 때문에 못 하는 일이 있어요. 한 명이 많이 한 건지 여러 명이 조금씩 한 건지 구분하지 못하고, 사람과 봇도 나누지 못해요. 탭을 갑자기 닫으면 마지막 묶음이 사라질 수 있어요. 키는 손으로 추가하고, 숫자를 보고서로 옮기는 곳마다 새 키의 칸도 따로 만들어야 해요. 그 대신 새어 나갈 플레이어 정보가 없고, 표 전체를 한눈에 읽을 수 있을 만큼 작아요.
