옛 앱 빌드를 위한 버전 게이트

작성 2026-11-24 · catchmeif404

웹 페이지는 다음에 열면 새로 바뀌어요. 모바일 앱은 그렇지 않아요. 사람들은 설치한 빌드를 계속 쓰고, 백엔드는 그 빌드에도 계속 답해야 해요. API 변경이 옛 빌드를 깨뜨리거나, 그냥 새 릴리스로 옮겨 오게 하고 싶을 때 서버가 그 뜻을 전할 수단이 필요해요. 피규어 수집 앱 figdex의 백엔드는 이를 위해 플랫폼마다 버전 두 개, 최소 버전과 최신 버전을 내려줘요.

값이 둘이고 효과가 달라요

앱은 GET /v1/app/config로 릴리스 설정을 받아요. 응답에는 해당 플랫폼의 minVersion, latestVersion, 스토어 주소가 들어 있고, 앱은 자기 버전을 두 값과 비교해요.

값이보다 낮은 앱사용자가 보는 것
minVersion막혀요앱이 업데이트 화면에서 멈추고, 서버도 API 호출을 HTTP 426으로 거절해요.
latestVersion계속 써요닫을 수 있는 안내가 떠요.

최신 버전은 권유이고 최소 버전은 요구예요. 일부러 나누어 두었어요. 그래야 몇 주 동안 모두를 새 릴리스 쪽으로 슬쩍 밀면서도 아무도 끊지 않을 수 있고, 강제 중단은 옛 빌드가 더는 동작할 수 없는 날을 위해 아껴 둘 수 있어요.

숫자 비교는 앱에서도 서버에서도 같은 규칙으로 해요. 버전은 1.2.3처럼 세 자리 숫자로 읽고, 앞에서부터 큰 자리 순서로 비교해요. 그래서 1.10.0이 1.9.0보다 높게 계산돼요. 웹이나 데스크톱 같이 스토어가 없는 플랫폼은 버전을 확인하지 않고 서버에도 보내지 않아요.

서버도 막아요

설정 화면을 건너뛰는 앱, 예컨대 며칠 동안 켜 둔 앱이나 설정 요청이 실패한 앱이 그냥 통과해서는 안 돼요. 그래서 백엔드 필터가 /v1/ 아래의 모든 요청을 확인해요. 앱은 버전을 X-App-Version 헤더에, 플랫폼을 X-App-Platform 헤더에 담아 보내요. 버전이 그 플랫폼의 최소 버전보다 낮으면 필터가 426 UPGRADE_REQUIRED로 답해요. 설정 엔드포인트 자체는 제외해서 앱이 안내 내용을 읽을 수 있게 해요. 버전 헤더가 없는 요청, 예를 들어 웹 빌드나 curl은 버전을 검사하지 않아요.

같은 필터가 점검 모드도 처리하는데, 점검 중에는 503 MAINTENANCE로 답해요. 버전 게이트와는 별개의 스위치예요.

실수로 사람을 곤란하게 하지 않도록 두 가지를 챙겼어요. 비교하는 것은 앱 pubspec 버전의 이름인 1.2.3 부분뿐이고, 더하기 기호 뒤의 빌드 번호는 보지 않아요. 그리고 읽을 수 없는 버전은 알 수 없는 값으로 취급해서 비교도 차단도 하지 않아요. 설정이 잘못돼도 모두를 잠그지 않기 위해서예요.

최신 버전이 스토어를 기다리는 이유

설정 옆에 적어 둔 규칙은 단순해요. 출시 뒤 강제 업데이트는 새 빌드가 스토어에 열린 것을 확인한 다음에 해요. 최소 버전을 먼저 올리면 받을 버전이 없는 사람이 막혀요. 최신 버전도 같은 이유가 적용돼요. "새 버전이 있어요"라는 안내는 약속이에요. 스토어가 아직 빌드를 열지 않았다면 눌러서 가도 옛 버전만 보여요.

Android는 이 과정이 자동이에요. 릴리스 워크플로가 앱을 Google Play에 올린 뒤 Play Developer API로 내부 테스트 트랙에 해당 버전 코드가 보이는지 최대 20분 동안 확인해요. 보일 때만 내부 엔드포인트 POST /v1/internal/app-release/latest를 호출해 latestVersion을 올려요. 이 단계는 릴리스 키가 설정된 경우에만 돌아요. 제때 빌드를 찾지 못하거나 키가 없으면 워크플로는 알림만 남기고 실패 없이 넘어가고, 사람이 관리자 화면에서 직접 값을 올려요. iOS도 같은 관리자 화면을 써요.

이 엔드포인트는 보수적으로 동작해요. 현재 값을 보내면 아무것도 바뀌지 않아요. 더 낮은 값을 보내면 409로 거절해서 최신 버전은 앞으로만 움직여요. 또 최신 값만 바꿔 쓰기 때문에, 관리자가 방금 저장한 최소 버전이나 점검 설정을 되돌리지 못해요. 모든 변경은 감사 로그에 남아요.

그래서 릴리스를 마친 뒤의 순서는 이렇게 돼요. 먼저 스토어에서 빌드가 열렸는지 확인하고, 열렸으면 최신 버전을 올려서 옛 앱에 안내를 띄워요. 최소 버전은 그다음에 필요할 때 따로 올려요. 순서를 거꾸로 하면 안내가 가리키는 곳에 받을 파일이 없어요.

최소 버전을 올리는 건 나중의 별개 결정이에요

자동 단계는 minVersion을 건드리지 않아요. 닫을 수 있는 안내만 띄워요. 강제 업데이트는 새 빌드가 스토어에 있는 것을 확인한 뒤에 의도해서 하는 일이고, 옛 빌드의 문을 실제로 닫는 것도 이 단계예요. 두 값을 따로 두었기 때문에 릴리스의 일상적인 부분만으로는 누구도 잠기지 않아요.

초기값은 환경 변수에서 와요. FIGDEX_ANDROID_MIN_VERSION과 최신 버전, iOS, 스토어 주소용 변수가 있고 기본값은 1.0.0이에요. 관리자가 설정을 한 번 저장하기 전까지만 쓰이고, 그 뒤에는 저장된 값이 우선해요.
