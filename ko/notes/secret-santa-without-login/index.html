로그인 없이 마니또 돌리기

작성 2026-11-24 · catchmeif404

마니또는 짧게 열렸다 닫히는 작은 모임이에요. 연말 교환 한 번을 위해 열두 명에게 가입하고, 메일 인증하고, 비밀번호를 외우라고 하면 절반은 떠나요. 그래서 산타픽(santapick.catchmeif404.com)은 로그인을 아예 만들지 않았어요. 그러면 질문이 두 개 남아요. 서버는 지금 요청한 사람이 누구인지 어떻게 알까요? 그리고 이 게임이 통째로 기대고 있는 비밀, 누가 누구에게 주는지는 어떻게 지킬까요?

링크는 두 종류예요

접근 방법은 두 가지이고 하는 일이 달라요.

  • 참가 코드는 방을 가리켜요. 여섯 글자이고 단톡방에 공유하며, 초대 페이지는 /j/CODE예요. 코드를 알면 닉네임과 위시리스트로 방에 들어갈 수 있지만, 다른 사람에 대한 정보는 읽을 수 없어요.
  • 개인 토큰은 한 사람을 가리켜요. /p/TOKEN의 비밀 부분이에요. 이 링크를 가진 사람이 곧 그 사람이에요. 위시리스트를 고치고, 상자를 열고, 익명 쪽지를 보내고, 산타를 맞힐 수 있어요.

둘은 일부러 다르게 만들어요. 참가 코드는 사람이 읽고 입력할 수 있어야 해서 헷갈리는 글자(0, O, 1, I)를 뺀 알파벳으로 만들어요. 토큰은 사람이 칠 일이 없으니 crypto.getRandomValues로 뽑은 24바이트를 URL에 쓸 수 있는 32글자로 인코딩해요.

export function newToken(): string {
  return base64url(randomBytes(24));
}

export function newJoinCode(length = 6): string {
  return Array.from(randomBytes(length), (b) => CODE_ALPHABET[b % CODE_ALPHABET.length]).join("");
}

토큰은 해시로만 저장해요

토큰은 주인의 링크에 한 번 담겨 나가고, 서버에는 SHA-256 해시만 남겨요. participants 테이블에는 유니크 제약이 걸린 token_hash 열만 있고 토큰 자체를 담는 열은 없어요. 사람을 찾을 때는 들어온 토큰을 해시해서 그 값으로 조회해요.

const hash = await hashToken(token);
const me = await db()
  .prepare("SELECT id, room_id, nickname, is_host FROM participants WHERE token_hash = ?")
  .bind(hash)
  .first<ParticipantRow>();
if (!me) return fail(ApiError.NotFound);

토큰은 사람이 정한 비밀번호가 아니라 192비트짜리 무작위 값이라서 솔트 없는 SHA-256만으로도 충분해요. 추측할 것도, 사전에서 찾아볼 것도 없으니까요. 해시로 저장해서 얻는 건, 데이터베이스를 내보내거나 쿼리 결과를 잘못 보거나 디버깅을 하더라도 그 안에서 바로 쓸 수 있는 링크가 나오지 않는다는 점이에요. 코드베이스 규칙은 단순해요. 토큰을 로그에 남기지 않고, 다른 사람의 토큰을 응답에 담지 않아요. 보관 기간이 지난 방은 없는 방으로 처리하고, 매일 도는 작업이 지워요.

방장도 접근 방식은 같아요. 방을 만들 때 방장 토큰이 만들어지고 똑같이 동작해요. 방장 표시는 추첨 같은 방장 전용 동작만 열어 줘요.

서버는 공개 전에 내 산타를 보내지 않아요

해시는 링크를 지켜 줘요. 더 어려운 비밀은 추첨 결과예요. 화면을 연 사람은 브라우저의 네트워크 통신을 볼 수 있으니, 믿을 수 있는 규칙은 응답에 그 데이터가 아예 없는 것뿐이에요.

그래서 방 페이지에 쓰이는 데이터는 loadView 함수 하나만 만들어요. 클라이언트 컴포넌트는 전부 RoomView 타입을 받는데, 이 타입에는 토큰도 없고 보는 사람 외의 해시도 없고 공개일 전에 "내 산타가 누구인지"를 담는 필드도 없어요. 함수 안에서 배정 정보를 읽기는 하지만 거기서 뽑아내는 건 세 가지예요.

  1. 내가 선물할 사람. 누구에게 주는지는 알아야 하니까요.
  2. 그 사람과 주고받은 쪽지, 그리고 이름 없이 표시되는 내 산타와의 쪽지.
  3. 교환일 맞히기 게임용 힌트 두 개. 산타가 보낸 쪽지 수와 산타 닉네임의 글자 수예요.

산타의 이름은 reveal 가지 안에만 들어가요. 이 가지는 방이 공개 단계이고, 공개 방식이 허용하고, 내가 이미 추측을 제출했을 때만 만들어져요. 아니면 { shown: false }만 나가요. 전체 짝 목록은 방장이 모두 공개하는 방식을 골랐을 때만 붙어요.

const revealShown =
  phase === Phase.Reveal && room.reveal_mode !== RevealMode.None && myGuess !== "";

영리한 검사보다 한 곳에 모아 두는 게 더 중요해요. 화면마다 응답을 따로 만들면 다음 기능이 언젠가 누출되는 필드를 하나 얹게 돼요. 만드는 함수와 타입이 하나면, 새 기능 리뷰는 함수 하나를 보는 일이 돼요.

이 설계의 대가

비밀번호처럼 쓰이는 링크에는 늘 같은 약점이 있어요. 누가 그 링크를 전달하면 그 사람이 곧 나예요. 복구도 안 돼요. 링크를 잃어버리면 메일로 다시 들어올 수 없어요. 메일이 없으니까요. 몇 주짜리 게임이라 그 정도는 받아들였고, 토큰은 주인이 연 그 페이지 말고는 어디에도 나가지 않게 했어요. 쓰기 요청은 우리 사이트에서 보낸 POST만 받아서 다른 사이트의 폼 전송을 막아요. 교환일 30일 뒤에는 데이터를 지우니까, 잃어버린 링크가 문제가 될 즈음에는 잃을 것도 많지 않아요.
